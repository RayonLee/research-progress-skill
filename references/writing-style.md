# 六类写法规范

## 结构

1. 标题：`YYYY年M月D日 <中文名>研究进展`（与文件名同名，不带任何后缀；中文名取 config.json 的 `report_name_cn`，下文示例用「李某」）
2. 本周进展概述（六类）
3. 下周进展计划（六类）
4. 论文计划表（7 列，原样继承上期）

六类固定顺序：**内参 / 项目 / 论文 / 课题 / 基础学习 / 其他**

## 核心：精炼精要

宁可少写，不要堆砌。

| 维度 | 规则 | 反例（勿学） | 正例 |
|---|---|---|---|
| 篇幅 | 每类 1–2 句，**12–110 字**；六类合计 **300–400 字** | 单类铺 300 字 | 内参 12 字 |
| 句式 | 动词开头（完成 / 整理 / 测试 / 看 / 推进 / 阅读），分号并列同类事项，句末一个句号 | — | 完成商务智能教材翻译复核与高清原图替换；中日问卷修订 |
| 细节 | 只保留「数量 + 对象」，**不列文件名、版本号、字数、意见来源** | （3500 字修改稿、按某院长意见修订稿、按论坛意见增补稿） | 完成 3 篇智库文章。 |
| 合并 | 同类事项合并计数，**不逐份列标题** | 逐份列出 3 份建议全名 | 完成 3 篇智库文章。 |
| 收尾 | 允许「等」收尾 | — | 阅读《Co-Existence》等书籍 |
| 英文 | 专有名词保留英文原形，不加书名号 | — | youtube / grok bot / Qorder / Trae |
| 下周计划 | 每类 1 句，**20–45 字**；无推进写「暂无。」 | 根据专家意见继续修改……推动……定稿 | 内参：暂无。 |

**归零率提醒**：生成后若六类合计超过 500 字，视为未按定稿尺度收敛，**必须重写**。

## 尺度示例（脱敏演示，非真实周报）

以下示例只用于校准「每句多长、合并到什么程度」的手感；条目内容为演示性质。

> 1.内参：完成 2 篇专题文章。
> 2.项目：完成教材译稿复核与图表替换；完成合作问卷修订；完成两场访谈素材抓取；以近期讲座为题做平台抓取尝试。
> 3.论文：完成一项混合方法研究设计与访谈方案；完成一项研究计划书；看某选题如何对已抓小规模数据做探索实验。
> 4.课题：完成教学改革创新项目等申报填写。
> 5.基础学习：阅读专业书籍若干；学习研究方法设计；继续进行认证课程学习。
> 6.其他：整理工具发展思考形成开源项目；测试多智能体系统使用边界、试验若干效率工具；2 场会务；博士申请人面试；优化现有数据抓取脚本。

> 下周：内参：暂无。 / 项目：等待合作报告下一步推进。 / 论文：推进访谈实施；启动新研究；阅读相关文献。 / 课题：暂无。 / 基础学习：继续按改写方向阅读论文。 / 其他：继续工具的测用和例行任务设置。

## 论文计划表：原样继承

**硬规则：全部内容从上一期 DOCX 的第一个表格照抄**（列名、行数、每个单元格文字，含 Submitted / Accepted / Writing 状态、拟完成时间、作者、数据来源、研究方法、进展情况及存在问题）。

- 实现方式：渲染时传 `--papers-from <路径>`，渲染器把 `content.json` 里的 `papers` 整个覆盖掉；**无需也不得在 `content.json` 里手写论文行**
- **推荐用 JSON 基线** `progress_auto/papers.json`（`{"columns": [...7列...], "rows": [[...], ...]}`）。它人可读可改，用户说「改某行状态」时直接改这个文件；渲染器也支持直接读 DOCX 表格

### 为什么不能从记录推断

论文是长期工作，极少出现周级动态；记录来源多为文档格式修改和版本迭代，**不能反映论文实质进展**。

已实测教训：旧版把「期间跟踪社交平台信息再分发相关文献」这类周报叙述写进了状态列，导致：

- 状态列失去可读性（应只有 `Submitted` / `Accepted` / `Writing` 这类纯状态）
- 单元格文字变长撑高行高，整张表超过一页，表头与数据行被拆到两页

### 本期论文有更新怎么办

**不改。** 用户在每周审批生成的 Word 时直接指出要改哪一行哪一列，由人确认后再改；改后的版本自然成为下一期的继承基准。

只有用户**明确要求**新增选题时，才在表格末尾追加新行（需同时提供 7 列内容）。

### 上期源解析顺序

1. `progress_auto/state.json` 的 `last_output`（上一期本地 DOCX）
2. 若缺失，从云端存档文件夹（config.json 的 `archive_folder_id`）按文件名日期取最新一份下载到 `refs/` 作为上期源
3. 两者都没有 → `render_docx.py` 退出码 4 停止，**不静默产出缺少论文表的文档**

首次部署（无任何上期文档）时，手动放一份含完整论文表的参考 DOCX 到 `refs/` 作为首期基准。

## content.json 结构

只写内容，不写格式：

```json
{
  "title": "2026年12月2日 李某研究进展",
  "summary": [{"no": "1.", "label": "内参：", "text": "..."}],
  "plan":    [{"label": "内参：", "text": "..."}]
}
```

- `summary`：`no` 是手写编号（`1.` ～ `6.`，渲染为加粗），`label` 含全角冒号
- `plan`：**没有 `no` 字段**，编号由 Word 自动生成（`numId=1`），文本不得再拼编号
- `papers` 不写，由 `--papers-from` 注入
